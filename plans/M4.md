# M4 — Live Trace: Detailed Plan

Goal: the headline experience ([PLAN.md](../PLAN.md) §3.3, §6 M4) — drag a slider, watch the
reflections move. A debounced, cancellable background pipeline recomputes the trace on every
edit; the trace panel grows axis modes (mV / mρ / Ω, time / distance) and two draggable
measurement cursors with Δ readout; cable spectra are memoized so repeated recomputes don't
re-evaluate cable models.

Starting point: M3's editor already recompiles the document on every mutation (badges, dirty
flag) and simulates on demand via a button; plotting lives in
[MainWindow.xaml.cs](../src/TdrSim.App/Shell/MainWindow.xaml.cs) (`PlotTrace`). The engine
has no cancellation and no caching: every `Simulate` call rebuilds `CableModel`s
([ChainSolver.cs:30](../src/TdrSim.Core/Engine/ChainSolver.cs),
[NetworkCompiler.cs:89](../src/TdrSim.Core/Engine/NetworkCompiler.cs)) and re-evaluates
`EvaluatePerMeter` per segment per frequency
([ChainSolver.cs:72](../src/TdrSim.Core/Engine/ChainSolver.cs),
[NodalSolver.cs:150](../src/TdrSim.Core/Engine/NodalSolver.cs)).

**Architecture decisions**

1. **Memoize Z′(f)/Y′(f) per cable model, not γl per (spec, length, grid).** PLAN §3.3
   suggested keying on length; keying the spectrum arrays on `(CableModel, grid)` instead is
   strictly better: the per-meter arrays are length-independent, so dragging a *length*
   slider still hits the cache (lengths only multiply), and the exp/sinh inside the stamps
   depends on length so it could never be cached anyway. What the cache eliminates is the
   expensive part — the Djordjevic-Sarkar dielectric evaluation and skin-effect math per
   (segment, frequency).
2. **Grid-change discipline makes the cache effective.** `FrequencyGrid.Build` already
   quantizes M to powers of two with dt fixed by rise time, so the grid — and therefore the
   cache key — only changes when the total delay crosses an octave or the rise time changes.
   Within an octave, every edit reuses the cached spectra.
3. **Two-stage recompute: fast preview, then full resolution.** The default demo needs
   M = 2^17 (131k samples, ~160 ms cold) — above the 50 ms live target on its own. Live runs
   therefore first compute a preview with the grid capped at 2^15 (dt stretches; edges
   soften slightly), publish it, and run the full-resolution pass after 250 ms of idle.
   32k-class solves measured 20–26 ms in M2, comfortably inside the target. (If the final
   grid is already ≤ 2^15 the preview *is* the final — one run.)
4. **The live state machine lives in Core** (`LiveTraceRunner`): debounce, latest-wins,
   cancellation, and preview/final staging are pure async orchestration with no UI types, so
   they get real unit tests; the shell just forwards mutations in and dispatches traces out.
   Same testability-first precedent as M3's document compiler.

**Definition of done**

1. All existing 134 tests plus the new Core tests green; build clean (warnings as errors).
2. Live updates: dragging the demo's cable-length slider moves the trace with no Simulate
   click. Preview latency ≤ 50 ms warm for 32k-class grids (measured and asserted on the
   4-node tee); the 131k demo's full-resolution pass lands after the drag settles. Rapid
   scrubbing never errors and never lets a stale run overwrite a newer one.
3. Cached and uncached runs produce bitwise-identical Γ(f) (asserted for both solver paths).
4. Axis modes (y: mV / mρ / Ω; x: time ns / distance m with a display-VF box) switch
   instantly from the stored trace, no recompute. User zoom survives live updates; a Fit
   button and first-trace autoscale handle the rest.
5. Two draggable cursors with per-cursor readout and Δ readout (time and distance both) —
   the classic distance-to-fault workflow.
6. Settled / grid-compromised warnings surface on final runs (not flickering previews);
   a progress shimmer appears when a run exceeds 200 ms; the last good trace stays visible
   while the document has fatal issues.
7. Launch smoke passes, including a UIA pass that moves the length slider and observes the
   status line change without any button click.

**Out of scope** (M5: reference-trace overlay, noise + averaging, CSV/PNG export, fault
elements, undo/redo; M6: bounce diagram, trace↔canvas cross-highlighting, layer peeling).
The M2 perf levers (hoisting per-frequency plans, blocked assembly) stay in reserve — pull
them only if step 8's measurements miss the targets above.

## Step 1 — Simulation session + spectrum cache (`Core/Engine/SimulationSession.cs`)

A reusable, app-lifetime cache object (nullable everywhere — null keeps today's behavior
and leaves existing tests untouched):

- `SimulationSession`:
  - `CableModel GetModel(CableSpec spec)` — persistent `CableSpec → CableModel` cache
    (record value equality; `with`-cloned override specs share the attenuation list
    reference, so equality and hit rates are exact). Replaces the per-call caches in
    `NetworkCompiler.Compile` and `ChainSolver.Solve` when a session is supplied.
  - `CableSpectrum GetSpectrum(CableModel model, FrequencyGrid grid, CableEvalOptions o)` —
    `Complex[] ZPerM/YPerM` of length M/2+1, filled in parallel on first request, keyed
    `(model, M, dt, options)`. Bounded: evict oldest beyond ~16 entries (a few MB each at
    2^17; typical sessions hold 2 grids × a handful of models).
  - Edge-trace cache: the reference edge (`Synthesize(ones, …)` in `TdrSimulator`) keyed by
    `(M, dt, riseTime, beta)` — it's a full IFFT recomputed identically on every run today.
- Solver integration: `ChainSolver`/`NodalSolver` `Solve` overloads take
  `(…, SimulationSession? session)`; the per-frequency loops index spectra by bin (both
  already iterate `n` over `freqs`), falling back to `EvaluatePerMeter` when session is
  null. `TdrSimulator.Simulate(model, instrument, settings, session, ct)` threads it
  through, including into `NetworkCompiler.Compile`.

Tests (`SimulationSessionTests`): warm run Γ(f) bitwise-equal to cold run on (a) a lossy
chain with connectors and (b) the demo tee (nodal); cache hit across a length change
(same spectrum instance reused — assert via reference or counter); grid octave jump misses
and refills; eviction keeps the entry count bounded; override-spec `with`-clones hit the
model cache.

## Step 2 — Cancellation through the engine

`CancellationToken` parameter (default `default`) on `TdrSimulator.Simulate`,
`ChainSolver.Solve`, `NodalSolver.Solve`, and `TracePipeline.Synthesize`:

- Both solvers pass `ParallelOptions { CancellationToken }` to their `Parallel.For`
  (cancellation checked per frequency, which is exactly PLAN §3.3's "per frequency block").
- `Synthesize` checks the token between stages (filter/window → IFFT → cumsum).
- Semantics: throws `OperationCanceledException`; no partially-written trace ever escapes.

Tests: a token cancelled mid-run (cancel after N bins via a spying frequency list or a
pre-cancelled token) throws `OperationCanceledException` promptly and a subsequent run with
the same session still produces correct (bitwise-equal to cold) results — cancellation must
never poison the cache.

## Step 3 — Live state machine (`Core/Engine/LiveTraceRunner.cs`)

The §3.3 pipeline as a testable class. Immutable snapshots make this clean: every edit
already produces a fresh `NetworkModel` (§3.2), so there is no locking anywhere.

- `Submit(NetworkModel, InstrumentSettings, SimulationSettings)` — called on every valid
  recompile; thread-agnostic.
- Behavior: 20 ms debounce; latest-wins (a newer Submit cancels the in-flight run and
  replaces any queued one — intermediates are dropped, never queued); preview run with
  `MaxLog2M` capped at 15, published via `TraceReady(trace, isPreview: true)`; after 250 ms
  idle, the full-resolution run publishes `isPreview: false` (skipped when the grids are
  identical). `RunStarted`/`RunFailed` events for the shimmer and status line. Debounce and
  idle delays are constructor parameters so tests can shrink them.
- One run in flight ever; runs use the shared `SimulationSession` and the step-2 token.

Tests (`LiveTraceRunnerTests`, tiny lossless networks so runs are ~ms): rapid-fire N
submits → exactly the last request's trace arrives last and is final; preview precedes
final and both match direct `Simulate` calls bitwise; cancelled intermediates raise no
`RunFailed`; submits during a run supersede it; dispose stops cleanly.

## Step 4 — Trace panel with axis modes (`App/Plot/`)

Plotting moves out of MainWindow code-behind into `Plot/TracePanel.xaml` (+
`TracePanelViewModel`), the §4 structure. The VM owns the latest `TdrTrace` (plus
preview flag) and the display state:

- **Y modes**: mV (`Volts × 1e3`), mρ (`Rho × 1e3`), Ω (clamped array as today). **X
  modes**: time (ns) or distance (m); distance uses a display-VF numeric box defaulting to
  `trace.DisplayVelocityFactor` (display-only — PLAN §3.1 "distance with VF choice").
  Switching modes replots from stored arrays instantly; no recompute.
- **Limit discipline**: the M3 auto-range heuristic runs on the first trace and on Fit;
  otherwise user zoom/pan is preserved across live updates (critical — the plot must not
  jump while dragging a slider). Switching an axis unit refits that axis only.
- Settled/Compromised warnings render as a corner annotation on final traces only.
- Preview traces draw identically (no dimming — they're correct physics, just softer dt).

## Step 5 — Measurement cursors (`App/Plot/`)

Two vertical cursors (A/B) via ScottPlot vertical lines, toggled from the panel, placed at
1/3 and 2/3 of the visible range when enabled:

- Drag: mouse-down hit-test within ~8 px (pixel→coordinate via `Plot.GetCoordinates`),
  suppress pan while dragging, mouse-move updates the line and readout (the standard
  ScottPlot 5 draggable-axis-line pattern — no built-in drag support).
- Readout (text block in the panel): per cursor the x in *both* units (ns and m) and the
  y of the nearest trace sample in the current y mode; plus Δt, Δdistance, Δy between
  cursors — the distance-to-fault workflow.
- Cursors live in x-time internally so axis-mode switches don't move them physically.

## Step 6 — Wire the live pipeline into the shell (`App/Shell/`)

- `ShellViewModel` owns the `SimulationSession` and a `LiveTraceRunner`; after every
  `Recompile()` with a usable model it calls `Submit` (fatal issues: no submit — the last
  good trace stays, badges explain). Runner events dispatch to the UI thread and feed the
  trace panel + status line (`preview`/`final`, solver, M, ms, settled).
- The Simulate button becomes a **Live toggle** (on by default) plus a **Refresh** button:
  live off = M3 behavior (manual runs — the escape hatch for huge networks), live on =
  submits flow automatically. Refresh forces a full-resolution run either way.
- Shimmer: a thin indeterminate progress bar over the trace panel appears when a run
  exceeds 200 ms (`RunStarted` + timer, hidden on `TraceReady`/`RunFailed`).
- Startup: the default document triggers one live submit — the app now opens showing the
  demo trace without any click (replaces M3's "press Simulate" placeholder title).

## Step 7 — Toolbar instrument quick controls (`App/Shell/`)

The §3.1 toolbar sketch: instrument preset dropdown and a rise-time slider next to the file
buttons, bound to the same `InstrumentViewModel` the inspector uses — the second headline
demo lever (slow the edge, watch close-in detail blur). Slider is log-scale 10 ps–5 ns
mapping to `RiseTimePsOverride`, with the effective value shown and a clear-to-preset
button. (Instrument changes flow through the existing mutation path, so they already
trigger live recomputes; rise-time changes change dt → new grid → cache refill, which is
exactly the expensive case the preview stage covers.)

## Step 8 — Performance verification

- `SimulationSessionTests` perf facts (same style as M1/M2 perf tests: generous asserted
  bound, measured value logged): warm-cache 4-node tee at 32k ≤ 30 ms median and ≤ the
  cold time; warm 131k demo tee logged informationally.
- Status line already shows per-run ms; verify by hand that scrubbing the length slider on
  the demo yields fluid preview updates and a crisp final trace on release. If the 50 ms
  preview target is missed, pull the reserved M2 levers before widening any targets.

## Step 9 — Smoke pass

Full test suite; UIA smoke extended from M3's script: launch → trace appears without any
click (live startup) → find the inspector length slider (select a cable first via UIA
selection or pre-select in the default doc… if selection automation is brittle, drive the
rise-time toolbar slider instead — same live path) → `RangeValuePattern.SetValue` → status
line changes to a fresh run → toggle an axis mode button → process alive. Manual
checklist: scrub length slider (fluid + final snap), zoom then edit (zoom preserved),
cursors drag with sane Δ, Live off/Refresh works, unsettled ring shows the warning,
fatal edit keeps last trace.

---

## Sequencing

1 → 2 → 3 in Core, test-first (the runner needs cancellation; the caches need bitwise
tests before anything consumes them). Then 4 (panel refactor + axis modes) and 5 (cursors)
— both independent of 1–3, only needing the stored `TdrTrace`. Then 6 (live wiring, needs
3 + 4) → 7 (toolbar lever) → 8 (perf) → 9 (smoke).

## Risks

| Risk | Mitigation |
|---|---|
| Cache returns stale physics after an edit (worst failure mode: wrong trace, silently) | Cache keys are value-complete: `(CableSpec→model, M, dt, options)`; bitwise cold-vs-warm equality tests for both solver paths; cancellation-then-reuse test proves cancelled runs can't poison entries |
| Races in debounce/cancel/supersede logic | The state machine is a Core class with deterministic tests (configurable delays, latest-wins and ordering asserted); UI only dispatches |
| 131k demo misses the live target | Two-stage preview (2^15 cap ≈ 20–26 ms measured in M2) + 250 ms idle full-res; M2 hoisting/blocked-assembly levers held in reserve |
| Plot churn: autoscale jumping or flicker during scrubbing | Limits preserved across updates by design (Fit is explicit); previews render identically to finals; stale trace retained on fatal issues |
| ScottPlot has no built-in cursor dragging | Manual hit-test + pan suppression is the documented ScottPlot 5 pattern; cursors are plain `VerticalLine` plottables, no exotic API |
| TextBox edits and slider drags spamming the runner | 20 ms debounce + latest-wins drops intermediates; preview cap bounds each run; one run in flight ever |
| Rise-time drags thrash the spectrum cache (dt in the key) | Expected and bounded: eviction cap ~16 entries; preview stage keeps it interactive; the slider commits on release (`LargeChange` drag), not per-pixel, if measurements demand it |
| PS 5.1 mojibake when editing files | All file edits via the Write/Edit tools only |
