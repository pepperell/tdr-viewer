# M7 — Component Bar: Detailed Plan

**Status: built 2026-11-22.** See "As built" at the end.

Goal: replace the long palette list down the left side with a row of square, graphical
buttons. Each button drops down its own short list; choosing an entry adds that
component. The 195 px left column goes away and the canvas takes the space.

Starting point: M0–M6 plus custom cables and the return-loss view. The palette was
`PaletteViewModel.Groups`: 12 groups, about 50 entries, in a `ScrollViewer`, added by
drag and drop only. Core needs **no changes**.

## The bar

One row, docked above the canvas and inspector, left-aligned. Nine buttons:

| Button | Does | Entries today |
|---|---|---|
| Cables | Drops down sections under headers: 50 Ω coax, 75 Ω coax, Other coax, Custom cables (only when there are any) | 10 + 4 + 1 + custom |
| Pairs | Drops down the "Balanced pairs" section | 6 |
| PCB traces | Drops down the "PCB traces" section | 5 |
| Ideal | Drops down the "Ideal (lossless)" section | 2 |
| Splices | Drops down the catalog connectors | 2 |
| Loads | Drops down Open, Short, Resistor, Capacitor, Inductor, Series RLC, Parallel RLC | 7 |
| Faults | Drops down the catalog faults | 4 |
| Probe | Adds a probe point straight away (no list) | |
| Cable manager | Opens the custom-cable dialog (replaces the "Custom cables…" button) | |

- Each button is 68 × 68 px: a 32 px icon above a subtitle. A thin divider separates
  Cable manager from the add-buttons, since it opens a dialog and adds nothing.
- Icons are stroke-only vector geometries, one weight, in the button's text colour.
  No image files.

| Button | Icon |
|---|---|
| Cables | Coax in cross-section: two concentric circles and a centre dot |
| Pairs | Two strands crossing twice (a twisted pair) |
| PCB traces | A board outline with a routed trace and two pads |
| Ideal | A plain straight line between two dots |
| Splices | Two cable ends meeting in a sleeve |
| Loads | A resistor zigzag to a ground symbol |
| Faults | A line broken by a lightning bolt |
| Probe | A probe tip touching a dot on a line |
| Cable manager | A small coax cross-section beside the lines of a list |

## Decisions

1. **Choosing an entry adds the node; there is no dragging out of a drop-down.**
   The node lands at the centre of the visible canvas and is selected. If a node is
   already there, it steps down-right by 30 px until it finds a free spot. Drag and drop
   from the palette is removed with the list.
2. **Drop-downs are `ContextMenu`s opened under the button**: arrow keys, Enter, Esc
   and click-away come free. Right-click opens the same list in the same place. Section
   headers in the Cables menu are non-selectable rows.
3. **Junction is renamed Probe in the UI and keeps its node kind.** (Decided by Andy,
   2026-11-22.) The Probe button adds the document's `Junction` node; the inspector
   calls it Probe. Files and examples that contain junctions load, draw, simulate and
   save as before. No schema change. A tee is still several wires on one port.
4. **There is always exactly one TDR node, and it cannot be deleted.** (Decided by
   Andy, 2026-11-22.) No button adds one. Delete skips it and leaves it selected. A
   file saved without one (older versions allowed that) gets one back on load, placed
   left of the other nodes.
5. **The view model stays in the App and is checked by running it.** There is no App
   test project; adding one for nine buttons is not worth it.
6. **The bar sits above the canvas**, not in a strip where the list was.

## Work

**A. View model** (`PaletteViewModel.cs`)
- `PaletteButton` (id, title, tooltip, icon, action: menu / add / cable manager) with
  `Entries`; `PaletteEntry` is either a `PaletteItem` or a `PaletteHeader`.
- Cables takes the three coax sections plus any section the other buttons do not
  claim, so a new catalog section is never lost; custom cables follow, synced live.
- The Instrument and Wiring groups and `IsCustomCables` go.

**B. Editor** (`EditorViewModel.cs`)
- `AddFromPalette(item, location)` applies the stepping rule and selects the new node;
  its TDR arm goes.
- `DeleteSelection` skips the TDR node.
- `LoadDocument` adds a TDR node when the document has none.

**C. View** (`MainWindow.xaml`, `MainWindow.xaml.cs`)
- The palette column goes; the grid is canvas | inspector.
- The bar: an `ItemsControl` over `Palette.Buttons`, `PaletteButtonStyle`, one
  `ContextMenu` per button bound to `Entries`.
- Automation ids: `Palette<Id>Button`; the cable manager keeps `CustomCablesButton`.
- The three drag-and-drop handlers go. The dialog's title becomes "Cable manager".
- The inspector's "Junction" becomes "Probe".

**D. Docs**: README (editor and probe paragraphs), TODO, PLAN.md.

## Done when

1. The left list is gone and the bar shows nine square buttons with icons and subtitles.
2. Every entry the old list had, except TDR instrument, can be added from a button.
3. Cables shows its sections under headers; a cable made in the cable manager appears
   under "Custom cables" without a restart.
4. An example containing junctions opens and simulates unchanged.
5. Undo removes a node added from the bar.
6. Select all + Delete leaves the TDR node.
7. `dotnet build` has no warnings and the Core tests pass.

## Not in this milestone

- A search or filter box (the menus are short enough).
- Recently used components.
- Renaming the `Junction` kind in the project file.
