# M6 — Teaching Extras: Detailed Plan

Goal ([PLAN.md](../PLAN.md) §3.4, §6 M6): the app starts *explaining* its own trace.
Three views, each answering a question the raw trace cannot:

- **Cross-highlighting** — "which component made this bump?" Hover the trace → the
  responsible component glows on the canvas; select a component → its stretch of the
  trace is shaded (and moves live while its slider is dragged).
- **Layer-peeling overlay** — "what is the impedance really, behind the ghosts?" The
  dynamic-deconvolution Z profile drawn over the raw Ω trace, including where it fails.
- **Bounce diagram** — "why is there a step *here*?" A lattice diagram for chain
  networks, every ray labeled with its ρ/τ product, time-aligned with the trace.

Starting point: M0–M5 plus the post-M5 work (examples menu, pulse view tab, 28-cable
catalog, automatic connector interfaces, slider-first inspectors) are complete. The
pieces M6 builds on already exist: `ChainExtractor` orders a chain source→far;
`DocumentIssue.NodeIds` already carries document ids for badges; the trace panel owns its
own mouse hit-testing (cursors) with ScottPlot input off and is always re-fitted; the
bottom `TabControl` (`ActiveViewIndex`) already hosts two views with a
compute-only-when-visible pattern (pulse). The solvers need **zero changes** — M6 is
analysis *of* the model and *of* the trace, never a new way to compute Γ(f).

**Architecture decisions**

1. **Everything analytical lives in Core and is pinned by tests; the App only draws.**
   Same precedent as the document compiler (M3) and `UndoStack` (M5). Three new Core
   units — `TraceFeatureMap`, `LayerPeeling`, `BounceDiagram` — each a pure function of
   (model | trace) with no session, no caching, no threading.
2. **Element provenance comes from the compiler, as a parallel list.**
   `DocumentCompilation.ElementOrigins` — one document node id per entry of
   `Model.Elements`, same indexing (SourcePort → the TDR node). Not a dictionary keyed by
   element: elements are records, so two identical parallel cables are *equal* and would
   collide. Consumers that hold element references (chain links) look up through a
   `ReferenceEqualityComparer` map built from the two lists. Auto-inserted interface
   hardware (mated pairs, adapters) keeps the owner it already has in
   `interfaceElements` and is additionally flagged (`ElementOrigin(NodeId, IsInterface)`).
3. **Cross-highlighting uses a first-pass delay map, for every topology.** Dijkstra over
   cable delays from the source net gives each net its earliest one-way arrival t(n). A
   cable between nets A/B with delay τ owns the round-trip interval
   `[2·min(tA,tB), tA+tB+τ]` — for a tree edge that is `[2tA, 2tB]`; for a ring edge
   reached from both ends it ends at the meeting point. Lumped things (loads, connectors,
   bridge/series faults, junctions) own a point at 2·t(n). This is exactly "computed from
   path delays" (§3.4) and it is honest about what a TDR can know: two branches at the
   same depth both light up, and past the deepest first-pass time the readout says
   *re-reflections only*. It needs no chain restriction and no ray tracing.
4. **Trace→canvas is hover; canvas→trace is hover *and* selection.** Hover is transient
   and free on the plot (we already process its mouse events). On the canvas both
   triggers shade the trace: hovering a node gives the quick "where is this?" sweep
   across the network, and selection keeps the shade alive while the inspector slider
   for that same node is dragged, so the span visibly slides along the trace — the single
   best teaching interaction in the milestone. Hover is drawn stronger than selection so
   the two are distinguishable when both are active.
5. **Layer peeling runs on the displayed trace, decimated, display-stage.** Like noise
   (M5 decision 4) it is post-`Simulate` processing in the shell at publish time, outside
   every cache. Input is the *displayed* ρ (noise included — a real instrument peels what
   it measured, and noise blowing up with depth is one of the failure modes worth
   showing). The O(N²) Schur recursion runs on a grid decimated to ≤ 2048 layers over the
   displayed extent (layers finer than ~t_rise/4 carry no information), so cost is a few
   ms regardless of M. It stops, and reports the cutoff, once the cumulative transmission
   Π(1−ρᵢ²) falls below 1e−3: nothing behind an open is recoverable.
6. **The bounce diagram is the textbook lossless lattice — deliberately not the engine.**
   Cables contribute nominal Z₀ and delay only; loss is ignored in ray amplitudes and the
   panel is annotated *approximate* whenever the network is lossy or reactive (§3.4). The
   gap between the lattice staircase and the simulated trace *is* the lesson, so the
   panel overlays both. Each interface's scattering (ρ, τ in both directions) comes from
   the real ABCD product of whatever resistive lumps sit at that node (shunt G, series
   R) between the two line impedances — one formula covers plain junctions, bridge
   faults, series faults and their combinations; the instrument is a semi-infinite Z_ref
   line, so the port is interface 0 and "what the TDR sees" is what transmits back
   through it. Reactive parts use their DC limit (shunt C open, series L through, shunt
   L short) and flag the interface.
7. **Ray growth is controlled by merging first, pruning second.** A time-ordered
   wavefront (priority queue keyed on interface, direction, quantized time) *sums* rays
   that coincide — commensurate lengths collapse from 2ⁿ paths to a polynomial lattice,
   as on paper. Then: drop |a| < 1 mρ, stop at the displayed time extent, hard cap
   2000 rays with a `Truncated` flag. **No ideal joints:** auto-inserted interface
   hardware (mated pairs, adapter bodies, excess lumps) is in the lattice exactly as it
   is in the model — its sections are real line sections with their own Z₀ and delay,
   its lumps real interfaces. Their few-mm delays are not commensurate with anything, so
   merging does not help them; the amplitude floor does (mated sections sit within a few
   percent of nominal, so their second-order rays fall under 1 mρ immediately), and the
   cap is the backstop. A dedicated test pins the ray count of a connectorized chain.
8. **No schema change.** All M6 state (peel toggle, hover, active tab) is session-only
   view state. Documents stay at the current version; nothing to migrate.

**Definition of done**

1. All existing tests plus the new Core tests green; build clean (warnings as errors).
2. `ElementOrigins` aligned with `Model.Elements` for every example project, including
   islands (omitted elements leave no entry) and interface hardware.
3. Hovering the trace highlights the first-pass owner(s) on the canvas and shows a
   one-line readout (component title, or "re-reflections only"); leaving clears it.
   Hovering or selecting node(s) on the canvas shades their span/marker on the trace in
   every axis mode (hover stronger than selection); the selection shade tracks live
   edits and survives replots. Works on chain, tee and ring examples.
4. Peel toggle draws the peeled Z profile over the Ω trace; on the lossless cascade it
   reads the true Z₀ of every section where the raw Z(t) is ghost-contaminated; the
   reliability cutoff is drawn; documented failures (loss creep, branches) behave as
   tested. Off = zero overhead.
5. "Bounce diagram" tab: for chains, interfaces labeled with component titles, rays
   colored by sign and weighted by magnitude, labels with the ρ/τ product, the lattice
   staircase over the simulated ρ on a shared time axis, *approximate* / *truncated*
   annotations; connector interfaces appear as their own (thin) sections, never as ideal
   joints. Non-chains show a clear "unbranched networks only" message.
   Computed only while the tab is visible.
6. Lattice arrivals reproduce the engine: cumulative port arrivals equal the simulated
   lossless plateaus (test-8 machinery) and the M5 fault closed forms.
7. UIA smoke extended: switch to the bounce tab and back, toggle Peel, select a canvas
   node; process stays alive, status shows a run. README and PLAN/TODO updated.

**Out of scope**: lattice diagrams for branched networks (ray count and the 2-D layout
both stop being teachable); loss-compensated or reactive-aware peeling; frequency-
dependent ray amplitudes; persisting any M6 view state; return-loss tab, Touchstone, custom cable entry (separate TODO items).

## Step 1 — Element provenance (`Core/Project/DocumentCompiler.cs`)

- `PartitionByConnectivity` already filters `(DocumentNode, Element)` tuples; keep the
  node alongside each surviving element and emit
  `ElementOrigins: IReadOnlyList<ElementOrigin>` (`record ElementOrigin(string NodeId,
  bool IsInterface)`), index-aligned with `Model.Elements`; entry 0 is the TDR node for
  the inserted `SourcePort`. Empty when `Model` is null.
- No behavior change anywhere else; `Probes`/`InterfaceNotes` untouched.

Tests (`DocumentCompilerTests`): alignment + count on the default document and every
`ExampleProjects` entry; an island's node id never appears; a mated-pair interface
yields `IsInterface` entries owned by the far cable; two identical parallel cables get
their own distinct origins (the reason this is a list).

## Step 2 — First-pass feature map (`Core/Engine/TraceFeatureMap.cs`)

- `TraceFeatureMap.Build(NetworkModel model, IReadOnlyList<ElementOrigin> origins)` →
  `Features` (`NodeId`, `StartS`, `EndS` in round-trip trace time; `EndS == StartS` for
  lumped), `DeepestS`. Dijkstra over cable delays `LengthM/(VF·c)`; connectors are
  zero-delay edges; interface sections add delay and fold into their owner's span.
  Junction nodes are not elements, so the map also takes the compiler's probe list
  (`DocumentProbe`) to place junction/load/bridge points by net.
- Queries: `At(double timeS, double toleranceS)` → node ids (spans containing t, plus
  points within tolerance; empty beyond `DeepestS + tolerance`), `For(string nodeId)` →
  that node's features.

Tests: chain — spans tile `[0, 2·Στ]` with no gaps, points sit on the joints; tee — both
branches own the same interval and `At` returns both; ring — each ring cable ends at the
meeting-point formula and the two spans meet; mixed VF — spans in time, not metres;
`At` past the far end → empty; tolerance picks up a load from either side.

## Step 3 — Cross-highlighting UI (`App/Plot/`, `App/Editor/`, `App/Shell/`)

- `ShellViewModel.Recompile` builds the map from `_compilation` (cheap, synchronous) and
  hands it to `TracePanelViewModel.FeatureMap`; null when there is no model.
- **Trace → canvas.** `TracePanel` mouse-move (when not dragging a cursor) converts x to
  trace time via the existing `TimeFromX`, sets `vm.HoverTimeS`; `MouseLeave` → NaN. The
  VM resolves `At(t, max(t_rise, 8 px))` and raises `HoverNodesChanged` only when the id
  set changes. The shell maps ids onto `NodeViewModelBase.IsTraceHighlighted` (new
  observable); the node template in [MainWindow.xaml](../src/TdrSim.App/Shell/MainWindow.xaml)
  gains a glow/border trigger. Panel bar shows a `HoverReadout`: "14.2 m · RG-58 30 m",
  several titles when branches coincide, or "re-reflections only — no first-pass owner".
- **Canvas → trace.** Two sources feed `TracePanel.HighlightSpans` (from `For(id)` per
  node, each tagged hover/selected): `Editor.SelectedNodes` changes, and a new
  `EditorViewModel.HoveredNode` set from `MouseEnter`/`MouseLeave` on the Nodify item
  container (an `EventSetter` pair in the existing `ItemContainerStyle` in
  [MainWindow.xaml](../src/TdrSim.App/Shell/MainWindow.xaml), forwarded by code-behind;
  cleared on leave, on node deletion, and when a drag starts so a dragged node does not
  strobe the plot). `Replot` adds the spans after `plot.Clear()` and before the signals:
  `Add.HorizontalSpan` for cables, a dashed `Add.VerticalLine` for lumped parts, through
  `XFromTime` so both x modes work; hover uses a stronger fill than selection.
  Hover/selection-only changes re-add spans without touching limits (always-fit stays
  stable).
- Hovering a canvas node never sets `IsTraceHighlighted` on it (that glow means "the
  trace is pointing at you"); the TDR node and the idle state highlight nothing.

## Step 4 — Layer peeling (`Core/Engine/LayerPeeling.cs`)

- `LayerPeeling.Peel(TdrTrace trace, double maxTimeS, int maxLayers = 2048)` →
  `PeelResult { double[] Ohms; double DtS; double StartTimeS; int ReliableCount;
  PeelStop Stop }`.
- Algorithm (lossless Schur / dynamic deconvolution): decimate ρ from t = 0 to `maxTimeS`
  onto `dt_p = max(Grid.DtS, span/maxLayers)`; difference to the sampled impulse
  response b₀; a₀ = unit impulse. Per layer i: `ρᵢ = bᵢ[0]/aᵢ[0]` (clamped to ±0.999),
  `Z_{i+1} = Zᵢ·(1+ρᵢ)/(1−ρᵢ)` from `Z₀ = Z_ref`, then
  `a_{i+1} = (aᵢ − ρᵢ·bᵢ)/(1−ρᵢ²)`, `b_{i+1} = shift(bᵢ − ρᵢ·aᵢ)/(1−ρᵢ²)` over the
  shrinking tail. Stop on transmission < 1e−3 (`Stop = Opaque`), clamp hit
  (`Stop = Unstable`), or end of data.
- `Z_ref` comes from the trace (`Ohms[0]` is the pre-edge Z_ref, as `RefitY` already
  relies on) — no new trace field.

Tests (`LayerPeelingTests`):
- *Algorithm pin, independent of the FFT pipeline:* synthesize the exact discrete-layer
  response of a known ρ sequence with a forward lattice loop; peel recovers it to 1e−9.
- *The headline:* test-8 lossless cascade (e.g. 50 → 75 → 30 → matched) at a fast rise:
  peeled Z on each plateau equals the true Z₀ ± 1 %, while raw `trace.Ohms` on the third
  section is off by more than that (asserts the ghost exists *and* is removed).
- Matched line → flat Z_ref ± 0.1 Ω. Open termination → `Stop = Opaque`,
  `ReliableCount` at the open ± a few layers.
- Documented failures (inequalities, not exact): lossy RG-58 100 m matched — peeled Z
  creeps upward monotonically (peeling reads loss as rising impedance); 50 Ω tee — reads
  ≈ 25 Ω at the junction, not the branch impedance.
- Perf: 2048 layers well under 10 ms (informational target, generous assert).

## Step 5 — Peel overlay UI (`App/Plot/`)

- `TracePanelViewModel.PeelEnabled` + `PeelResult? Peel`; the shell computes it in
  `PublishTrace` on the displayed (post-noise) trace when enabled, with `maxTimeS` = the
  same last-activity extent `AutoRange` uses (extract that scan into a shared helper so
  both agree). Toggling on recomputes from the current trace — no simulation.
- "Peel" check in the panel bar (tooltip: Ω mode only; lossless assumption). `Replot`
  draws it in Ω mode only: a second Signal in a contrasting color over the live trace,
  the part beyond `ReliableCount` dimmed, a short caption from `Stop` ("unreliable
  beyond 31.4 m — nearly total reflection"). Cursors keep sampling the raw trace.

## Step 6 — Bounce diagram model (`Core/Engine/BounceDiagram.cs`)

- `BounceDiagram.Build(NetworkModel model, IReadOnlyList<ElementOrigin> origins,
  double zRefOhms, BounceOptions options)` → null for non-chains
  (`ChainExtractor.TryExtract`), else:
  - `Interfaces`: position (cumulative one-way delay and metres), owning node ids,
    `S` (ρ/τ from each side), `IsReactiveApprox`;
  - `Rays`: `(FromInterface, ToInterface, StartS, EndS, Amplitude, Factors?)` —
    `Factors` (the ordered ρ/τ list) kept only for unmerged rays, `PathCount` otherwise;
  - `PortArrivals`: `(TimeS, Amplitude)` in ρ units, time-ordered;
  - flags `IsApproximate` (any lossy cable or reactive lump), `Truncated`.
- Construction per decisions 6/7: every cable link — interface sections included — is a
  line section; the lumps between two consecutive sections form one interface
  (`IsInterface` origins only affect labeling: "BNC mated pair", owned by the cable end
  it belongs to); terminal one-port
  ρ_L (open +1, short −1, R, reactive DC limit); wavefront propagation from a unit
  incident wave on the Z_ref side of interface 0.
- `BounceOptions`: `MaxTimeS`, `MinAmplitude = 1e-3`, `MaxRays = 2000`.

Tests (`BounceDiagramTests`):
- Two-segment mismatch: first three arrivals at 2τ₁, 2(τ₁+τ₂), 2(τ₁+2τ₂) with
  amplitudes ρ₁, τ₁ρ₂τ₁′, τ₁ρ₂ρ₁′ρ₂τ₁′ to 1e−12, and matching `Factors`.
- *Tie to the engine:* cumulative `PortArrivals` equal the simulated lossless trace's
  mid-plateau ρ ± 1e−3 for the case-8 cascade; the full sum converges to
  `trace.DcReflection` within the prune tolerance.
- Mid-line bridge and series fault first arrivals equal the M5 closed forms
  −Z₀/(2R+Z₀) and R/(R+2Z₀).
- Z_ref ≠ first-segment Z₀ (75 Ω instrument on 50 Ω cable): arrival at t = 0 with
  (Z₁−Z_ref)/(Z₁+Z_ref).
- Merging: N equal-delay sections → ray count bounded polynomially (assert a concrete
  bound), same arrivals as the unmerged enumeration on a small case.
- Flags: lossy cable → `IsApproximate`; capacitor termination → interface
  `IsReactiveApprox` with ρ = +1; tiny `MaxRays` → `Truncated`; tee document → null.
- No ideal joints: a mated-pair document yields one section per interface element with
  the mated spec's Z₀ and its mm-scale delay, the excess lump as a flagged interface,
  and a first arrival from the pair at 2·t(joint) with the closed-form mismatch ρ; an
  adapter document likewise shows its body section. Ray count for a connectorized
  three-cable chain stays under a pinned bound and is not `Truncated` at defaults.

## Step 7 — Bounce panel (`App/Plot/BouncePanel.xaml(.cs)`, `BounceViewModel.cs`)

- Third `TabItem` "Bounce diagram" (`ActiveViewIndex == 2`); the shell rebuilds the
  diagram on final trace publish and on tab activation, only while visible (pulse-view
  pattern). `MaxTimeS` = the trace panel's displayed extent so both views cover the same
  time span.
- Layout: two stacked `WpfPlot`s, input disabled, same x limits set by us (always-fit —
  no linking machinery needed), fixed left-axis width so the plot areas align.
  - Top strip: simulated ρ (mρ) vs time with the lattice staircase overlaid.
  - Bottom: time →, distance ↓ from the port; horizontal interface lines labeled with
    component titles; rays as line segments (slope = velocity), color by sign, width /
    alpha by |amplitude|; text labels on the strongest ~40 rays (amplitude in mρ).
- Hover a ray (own hit-test, nearest segment within 6 px): readout shows the product —
  "τ₁·ρ₂·τ₁′ = 1.20 · −0.43 · 0.80 = −0.413" or "Σ of 5 paths = +0.012" — and the
  canvas highlights the components at its two interfaces through the Step 3
  `IsTraceHighlighted` path.
- Connector interfaces are drawn like any other section. At full scale a few mm is a
  hairline, so their two interface lines share one label ("BNC mated pair") and
  ray-hover reports rays inside them normally; no special casing beyond label
  de-cluttering (labels closer than ~12 px merge).
- Caption line from the flags: "approximate: loss and reactive parts ignored",
  "truncated at 2000 rays". Non-chain or no model: centered message instead of the
  plots.
- ScottPlot calls (`Add.Line`, `Add.Text`, `Add.HorizontalSpan`, axis size pinning)
  verified at build time against 5.1.59, as in M4/M5.

## Sequencing

1 → 2 → 3 (provenance, map, highlighting: smallest slice, and it lays the provenance the
bounce labels need) → 4 → 5 (peeling: Core-first, independent of 1–3) → 6 → 7 (bounce:
largest, needs 1 and reuses 3's highlight path) → 8. Each of 3, 5, 7 is shippable on its
own; if the milestone is cut short, the order above is also the value order per effort.

## Risks

| Risk | Mitigation |
|---|---|
| Ray count explodes (2ⁿ bounces) | Merge coincident rays first, then amplitude floor, time limit and hard cap with a visible `Truncated` note; merging bound unit-tested |
| Lattice disagrees with the trace and looks like a bug | It is the lesson, but only if framed: staircase drawn over the simulated ρ, *approximate* caption whenever loss/reactance is present, engine-agreement test on the lossless case |
| Record equality collapses identical elements in provenance | Parallel index-aligned list; reference-equality lookups only; dedicated parallel-cables test |
| First-pass map over-promises (masking, ghosts, coincident branches) | Readout says "first-pass" and lists every owner at that depth; explicit "re-reflections only" past the deepest point |
| Peeling numerically unstable near total reflection or under noise | ρ clamp, transmission-product cutoff with a drawn reliability boundary, decimation to the edge resolution; failures are asserted behaviors, not surprises |
| Peeling cost on 2¹⁸-sample traces | Fixed ≤ 2048 layers over the displayed extent — O(4M) flops, off by default, perf-asserted |
| Hover handler fights cursor dragging | Hover path runs only when `_dragging == '\0'`; highlight updates only when the id set changes |
| Canvas hover strobes the plot during node drags / wire drawing, or sticks after a delete | `HoveredNode` cleared on drag start, on leave and on node removal; span-only updates never refit, so a hover change is one cheap redraw |
| Connector-interface sections (mm-scale, incommensurate delays) flood the lattice now that nothing is collapsed | Amplitude floor kills their second-order rays (near-nominal Z₀); hard cap as backstop; ray-count bound on a connectorized chain is unit-tested; label de-cluttering keeps the drawing readable |
| Two stacked plots drift out of x alignment | Input disabled on both, limits set from one place, left-axis width pinned; manual check across DPI scales |
| ScottPlot API names differ in 5.1.59 | Verified at build time before UI work in steps 3/5/7; fall back to plain `Scatter` segments and polygons |
| Scope creep into branched lattices or lossy peeling | Hard line in *Out of scope*; branched networks get the cross-highlight map, which already works for them |
| PS 5.1 mojibake when editing files | All file edits via the Write/Edit tools only |
