# M0 — Scaffold: Detailed Plan

Goal: a building, testable, runnable skeleton of the solution described in [PLAN.md](../PLAN.md)
§4, plus the catalog JSON schema with real datasheet data loaded and validated by unit tests.
No physics, no network model, no editor behavior — those start in M1/M3.

**Definition of done**

1. `dotnet build` succeeds with zero warnings (warnings-as-errors on).
2. `dotnet test` green: catalog deserialization + data-sanity tests.
3. `TdrSim.App` launches: window with a Nodify canvas (empty) and a ScottPlot panel showing a
   placeholder trace — proving both UI packages restore and render on .NET 10.
4. Git repository initialized with an initial commit of the scaffold.

**Explicitly out of scope** (deferred): `NetworkModel`/element types, γ/Z₀ evaluation,
attenuation fitting (k₁/k₂ least squares), FFT pipeline, any canvas interactivity. The catalog
*stores* datasheet-style data; M1 consumes it.

---

## Step 0 — Toolchain (.NET 10 SDK)

The machine has SDKs 8.0.422 and 9.0.315 only; .NET 8 and 9 both left support on
2026-11-10. PLAN.md targets .NET 10 LTS.

- Install: `winget install Microsoft.DotNet.SDK.10` (admin shell may be required).
- Pin: `global.json` at repo root — `"version": "10.0.100"`, `"rollForward": "latestFeature"`.
- Verify: `dotnet --version` reports a 10.0.x SDK from the repo root.
- Fallback if the install is blocked: temporarily target `net9.0`/`net9.0-windows` (everything
  else in this plan is unchanged), flag it in README, revisit before M1 ends.

## Step 4 — Catalog schema, data, and loader (the design work of M0)

### 4.1 Files

```
src/TdrSim.Core/Catalog/
  Data/cables.json                 # embedded resources (<EmbeddedResource>)
  Data/connectors.json
  Data/instruments.json
  Data/faults.json
  CatalogTypes.cs                  # records below
  CatalogLoader.cs                 # load + validate embedded JSON
  CatalogJsonContext.cs            # System.Text.Json source-gen context
```

### 4.2 Schema (v1)

Every file: `{ "schemaVersion": 1, "items": [ ... ] }`. Records are immutable
(`record` + `init`), all physical quantities in SI unless the name says otherwise
(datasheet-friendly units are kept where they match how users think: Ω/km, pF/m, dB/100 m, MHz).

**CableSpec** — stores datasheet-style parameters; derived quantities (k₁/k₂ fit, Rs,
Djordjevic–Sarkar params) are computed in M1, not stored:

```json
{
  "id": "rg58-belden-9201",
  "name": "RG-58 (Belden 9201)",
  "category": "coax",
  "z0Ohms": 52.0,
  "velocityFactor": 0.66,
  "capacitancePfPerM": 93.5,
  "rdcCenterOhmsPerKm": 33.8,
  "rdcShieldOhmsPerKm": 23.0,
  "dielectricConstant": 2.3,
  "attenuation": {
    "units": "dB_per_100m",
    "points": [
      { "mhz": 1, "db": 0.98 }, { "mhz": 10, "db": 3.61 }, { "mhz": 50, "db": 8.20 },
      { "mhz": 100, "db": 12.5 }, { "mhz": 200, "db": 18.4 }, { "mhz": 400, "db": 27.6 },
      { "mhz": 700, "db": 38.4 }, { "mhz": 900, "db": 45.0 }, { "mhz": 1000, "db": 47.6 }
    ]
  },
  "source": "Belden 9201 datasheet"
}
```

Initial data set (all values already gathered, datasheet-verified, in PLAN.md §1.6 research):
RG-58/9201, RG-6/1694A, RG-174/8216, RG-213/8267, LMR-400, Cat5e/1583A, Cat6/2413.
Twisted-pair entries use `"category": "twisted-pair"` and carry the TIA three-term IL
coefficients in an optional `insertionLossCoefficients: { k1, k2, k3 }` field instead of
(or in addition to) attenuation points.

**ConnectorSpec**:

```json
{ "id": "bnc-barrel", "name": "BNC barrel", "seriesResistanceOhms": 0.002,
  "seriesInductanceNh": 2.0, "shuntCapacitanceNearPf": 1.0, "shuntCapacitanceFarPf": 1.0 }
```

Entries: BNC barrel, F-connector, clean splice, corroded splice (series R dominant).

**InstrumentSpec** (from PLAN.md §1.5 table):

```json
{ "id": "tek-80e04", "name": "Lab sampling TDR (Tek 80E04 class)",
  "stepAmplitudeVolts": 0.25, "riseTime1090Ps": 23, "sourceImpedanceOhms": 50 }
```

Entries: tek-80e04 (250 mV/23 ps), tek-80e10b (250 mV/12 ps), tek-1502c (300 mV/200 ps/50 Ω),
catv-75 (75 Ω variant), cable-tester (2 V/2 ns), plus `"id": "custom"` sentinel handled in UI.

**FaultSpec** — parameterized cable-section overrides (consumed in M5, schema fixed now):

```json
{ "id": "water-ingress", "name": "Water ingress", "kind": "sectionOverride",
  "defaults": { "lengthM": 2.0, "z0Scale": 0.7, "extraGdB": 3.0 } }
```

### 4.3 Loader + validation

- `CatalogLoader.LoadEmbedded()` → `Catalog` aggregate (cables, connectors, instruments, faults).
- System.Text.Json with a source-generated `JsonSerializerContext` (fast, trim-safe),
  `PropertyNameCaseInsensitive = false`, unknown-property handling strict (catches typos in data).
- `Validate()` returns a list of errors: unique non-empty ids; `0 < VF ≤ 1`; `1 ≤ Z0 ≤ 1000`;
  capacitance/RDC positive; attenuation points sorted by MHz with increasing dB;
  `schemaVersion == 1`.

## Step 5 — Tests (`tests/TdrSim.Core.Tests/CatalogTests.cs`)

1. Embedded catalog loads without exception; validation returns zero errors.
2. Expected ids present (all 7 cables, 5+ instruments, 4 connectors).
3. Spot-check guards against data-entry typos: RG-58 `z0Ohms == 52.0` (not 50!), LMR-400
   `velocityFactor == 0.85`, Cat5e IL coefficients `(1.967, 0.023, 0.050)`, 1502C
   `riseTime1090Ps == 200`.
4. Round-trip: serialize → deserialize → equal records.
5. Validator negative tests: duplicated id, VF > 1, unsorted attenuation each produce an error.

## Step 6 — Build verification & commit

- `dotnet build TdrViewer.sln` (warnings-as-errors) and `dotnet test` from a clean clone state.
- Launch the app once manually; confirm canvas + plot render.
- `git init`, add all, initial commit.

## Sequencing & size

Steps 0–2 are mechanical (~an hour including SDK install). Step 3 is small but is the
*integration risk probe* — if Nodify or ScottPlot misbehaves on net10.0-windows we find out on
day one, not in M3/M4. Step 4 is the real design work (schema shapes the M1 engine API and M5
catalog polish). Total: roughly half a day to a day.

## Risks

| Risk | Mitigation |
|---|---|
| .NET 10 SDK install blocked (no admin / winget missing) | net9.0 fallback documented in step 0; isolated to `global.json` + `TargetFramework` lines |
| Nodify 7.3.0 or ScottPlot 5.1.59 restore/render issue on net10 | Smoke shell in step 3 surfaces it immediately; fallbacks: ScottPlot non-GL control (already the default choice), Nodify 7.2.x pin |
| Schema churn later (fields missing for M1 fitting) | `schemaVersion` field + loader tolerant only via explicit migration; keep records in one file for easy evolution pre-1.0 |
| Warnings-as-errors friction with generated/XAML code | Scoped `NoWarn` only in App csproj if a specific generator warning is noisy; never solution-wide |
