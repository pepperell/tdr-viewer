# M2 — General Networks: Detailed Plan

Goal: lift M1's chain-only restriction. A per-frequency **nodal admittance solve** (SPICE AC
analysis) handles arbitrary graphs — tees, stubs, bridged taps, stars, rings — with the M1
chain solver kept as the fast path for unbranched networks. Everything lives in
`TdrSim.Core`; the `TdrSimulator.Simulate` signature does not change, so the app and all M1
tests keep working untouched.

The M1 model types already describe general graphs; only the solver was restricted. M2 is
therefore pure engine work: a small dense complex LU, numerically stable Pi stamps, exact
short/open handling, and the dispatch switch — each pinned by closed-form tests
([PLAN.md](../PLAN.md) §5 cases 9 and 13, plus structural cross-checks).

**Definition of done**

1. Validation cases 9 and 13 green, plus the structural suite below (stub lattices, star,
   chain-vs-nodal equivalence, short folding); all M1 tests still green; build clean.
2. Chain networks still route through `ChainSolver` (asserted by a dispatch test); the M1
   10-segment benchmark stays ≤ 30 ms.
3. Nodal benchmark: 3-arm tee (4 nodes), M = 32768, median ≤ 30 ms; 31-node stress network
   logged, assert ≤ 500 ms (informational target ≤ 100 ms).
4. Optional demo: the app's hardcoded network gains an open stub, showing a branch live.

**Out of scope** (M3+): editor/UI, live updates, fault elements, noise/averaging, any
network larger than the editor will realistically produce (dense LU is the right tool for
N ≲ 64 nodes; sparse methods are deliberately not built).

## Step 1 — Dense complex LU (`Engine/ComplexLu.cs`)

In-place LU with partial pivoting over `Complex[]` (row-major, n ≤ ~64), single-RHS solve,
zero allocations after workspace creation (caller supplies buffers; the solver keeps them
thread-local). Returns a success flag with the smallest pivot magnitude; the caller decides
what a near-zero pivot means (see step 4's gMin policy).

Tests (pure, written first): reconstruct known solutions (build b = A·x for random
well-conditioned A up to n = 32, recover x to rel 1e−10); permutation correctness vs a
2×2/3×3 hand case; exactly singular matrix reports failure instead of NaN.

## Step 2 — Stable Pi stamps (`Engine/LineStamps.cs`)

The exact Pi equivalent of a line segment (PLAN §1.3):

```
Yser = 1/(Z0·sinh γl)         Ysh = tanh(γl/2)/Z0        (per side)
Y[i,i] += Yser + Ysh          Y[j,j] += Yser + Ysh
Y[i,j] −= Yser                Y[j,i] −= Yser
```

Three regimes, mirroring `TwoPort.Line`'s structure (all arguments have Re(γl) ≥ 0, so only
e^(−x) forms appear — nothing can overflow):

- **General**: with q1 = e^(−γl), q2 = e^(−2γl):
  `Yser = 2·q1 / (Z0·(1−q2))`, `Ysh = (1−q1)/((1+q1)·Z0)`, computing each `1−q` as
  `−ComplexMath.Expm1(−γl)` / `−Expm1(−2γl)` (no cancellation for small γl). For very lossy
  lines q1 underflows to 0 → Yser → 0, Ysh → 1/Z0: the far end decouples and the port sees
  matched Z0 — physically correct.
- **Small |γl| < 1e−4**: product forms that never touch Z0 alone:
  `Z0·sinh(γl) = Z'l·sinhc(γl)` → `Yser = 1/(Z'l·sinhc)`;
  `tanh(γl/2)/Z0 = (Y'l/2)·tanhc(γl/2)` with tanhc(u) = 1 − u²/3 + 2u⁴/15.
  At f = 0 (Y'l = 0, Z'l = R0·l > 0) this is exactly the series-resistance stamp.
- **Exact short** (|Z'l| = 0 at f = 0 on a lossless line): Yser is infinite — do **not**
  stamp; report "this branch is an ideal short" and let step 3 merge the nodes.

Connector stamp: series admittance 1/(R + jωL) between nodes (R = L = 0 → ideal-short
report, same as above) plus shunt jωC on each side. Loads reuse `LoadModel.ShuntAdmittance`
verbatim — `IsShort` becomes "merge this node with ground".

**Property test tying M2 to M1** (the net that catches stamp sign/convention bugs): for
random (γl, Z0) across all three regimes, terminating the Pi with load Z_L and solving the
2×2 must give the same Z_in as folding Z_L through `TwoPort.Line` — rel 1e−12.

## Step 3 — Graph compilation (`Engine/NetworkCompiler.cs`)

- `ChainExtractor.TryExtract(model)` → `Chain?`: same walk, returns null where `Extract`
  throws `NotSupportedException` (Extract stays; its unit tests still apply). The simulator
  dispatches on this.
- For non-chain networks, compile once per simulation: dense node indexing (NodeId → int),
  element list with endpoints resolved, validation identical to M1's rules (exactly one
  `SourcePort`, everything connected to it, positive lengths, `LoadModel.Validate`).
- Summary values the facade needs for any topology: **TotalCableDelayS** = Σ all segment
  delays (upper bound on the principal echo path — ring recirculation decays geometrically
  and is covered by the 6× window factor plus the `Settled` flag) and **DisplayVf** = VF of
  the first cable reached by BFS from the port.

## Step 4 — Nodal solver (`Engine/NodalSolver.cs`)

Per frequency (Parallel.For, thread-local Y/LU/RHS workspaces, no per-iteration allocation):

1. **Shorts first**: collect ideal shorts at this frequency (Short/0 Ω loads any f;
   inductive loads and lossless segments at f = 0; zero-impedance connectors; exact series
   resonances) and union-find them — node–node shorts merge nodes, node–ground shorts merge
   into the ground class. Port in the ground class → Γ = −1 immediately, no solve.
   Union-find is O(nodes) — cheap enough to run per frequency; no cached topology plans
   unless the benchmark says otherwise.
2. **Assemble** Y over the surviving representative nodes (stamps from step 2, loads on
   diagonals, merged nodes share rows/columns).
3. **gMin**: add 1e−12 S to every diagonal, at every frequency. PLAN §1.3 called for a
   port-only leak at f = 0; the generalization also regularizes interior nodes that float
   at DC (e.g. between two capacitors) and the measure-zero-but-reachable case of a
   lossless loop resonating exactly on a harmonic grid bin (the grid is harmonic, so exact
   hits are not improbable). Error bound: 1e−12 S against ~0.02 S line admittances → ~1e−10
   relative in Γ, inside every test tolerance. A non-finite guard after the solve backstops
   anything that still escapes.
4. **Solve** Y·v = e_port (1 A into the port node); Z_in = v_port;
   Γ = (Z_in − Z_ref)/(Z_in + Z_ref). All-open at DC: v_port = 1/gMin → Γ(0) = 1 − ~1e−10.

## Step 5 — Dispatch (`Engine/TdrSimulator.cs`)

`TryExtract` succeeds → `ChainSolver` (unchanged M1 path); otherwise → `NodalSolver`. Grid
sizing uses the compiler's TotalCableDelayS for both paths (for chains it equals the M1
value). Public API, trace record, and pipeline are untouched.

## Step 6 — Validation tests (`ValidationTests` additions + `NodalTests.cs`)

All lattice cases use one VF everywhere so event times coincide exactly; plateaus measured
mid-interval as in M1; `AssertHermitian` on every trace. Junction rule used below: m equal
lines meeting at a node give ρ = (2−m)/m; voltage transmission into the junction is 2/m.

| Case | Network (lossless 50 Ω, matched 50 Ω source) | Closed form | Tolerance |
|---|---|---|---|
| 9 | 30 m feed → tee, two 30 m arms each → 50 Ω | plateau ρ = −1/3 from t_j on; Γ(0) = −1/3 exactly (50∥50 at DC) | 2e−3; DC 1e−9 |
| 9b | 30 m feed → tee: 10 m **open stub** + 30 m through → 50 Ω | plateau sequence p_k = (−1/3)^k at t_j + (k−1)·2d/v → settles to 0 (stub invisible at DC) | 2e−3 on p1..p4; DC 1e−9 |
| 9c | same, stub **shorted** | p_k = 2·3^(−k) − 1 → −7/9, −25/27, … → −1; Γ(0) = −1 | 2e−3; DC 1e−12 |
| 9d | 4-way star: feed + three 30 m arms each → 50 Ω | plateau ρ = −1/2; Γ(0) = −1/2 | 2e−3; DC 1e−9 |
| 13 | 30 m feed → **ring**: two arms 10 m and 20 m rejoining, far side open | every circulating path is 30 m, so events land at t_j + k·τ_ring with plateaus p_k = 1 − 4·3^(−k) (−1/3, 5/9, 23/27, …) → +1 | 2e−3 on p1..p4; DC 1e−9 |

Structural cross-checks (`NodalTests.cs`):

- **Chain-vs-nodal equivalence** — the single strongest net: a lossy 5-segment chain with
  mid-chain shunt loads solved by `ChainSolver` and by `NodalSolver` (dispatch forced both
  ways) agrees on Γ across the whole grid to 1e−9. Runs on real RG-58 so skin, dielectric,
  and DC paths are all exercised.
- **Short folding**: a mid-chain Short makes everything beyond it invisible — equal traces
  (1e−12) for the full network vs the network truncated at the short; short at the port
  node → ρ ≡ −1.
- **All-open at DC**: tee of open stubs settles to Γ(0) within 1e−9 of +1 (gMin bound).
- **Dispatch**: a chain network and a branched network each produce the expected solver
  path (observable via an internal diagnostic on the compiled result, asserted in tests).
- **Lossless ring Settled flag**: the case-13 ring settles (geometric decay) — but a
  **resonant open-ended ring variant** that rings past the window must set Settled = false
  rather than silently truncating.

## Step 7 — Performance

- Tee benchmark (4 nodes, 3×30 m RG-58, M = 32768): warm median of 5 via Stopwatch, logged;
  assert ≤ 30 ms. This matches the M1 benchmark budget — at 4 nodes the LU is negligible
  next to cable evaluation, so branching must be ~free at editor scale.
- Stress benchmark (tee of three 10-segment arms: 31 nodes, mixed loads, M = 32768):
  logged; assert ≤ 500 ms, target ≤ 100 ms. O(n³) LU at n = 31 is ~30 k complex mults per
  frequency; if the target is missed, first lever is hoisting the union-find/index plan out
  of the frequency loop (two plans: f = 0 and f > 0), second is blocked assembly.
- Re-run the M1 chain benchmark unchanged (fast path must not regress).

## Step 8 — Demo wiring (optional, small)

Extend the app's hardcoded demo with a branch: 30 m RG-58 → tee with a 10 m open stub →
20 m RG-58 → open. The trace shows the −1/3-family dip at the tee, the stub's alternating
echo train, and the final open — the first visible proof of M2 capability. Still throwaway
(M4 replaces it).

## Sequencing

1 (LU, pure math, test-first) → 2 (stamps + the TwoPort.Line property test) → 3 (compiler/
TryExtract) → 4 (nodal solver) → 5 (dispatch) → 6 (validation; the equivalence test comes
first — it catches most assembly bugs before the lattice cases need interpreting) → 7
(perf) → 8 (demo). Steps 1–2 are independent and could be done in either order.

## Risks

| Risk | Mitigation |
|---|---|
| Singular Y on lossless resonant loops (harmonic grid can hit resonance exactly) | Always-on gMin (documented deviation from the f=0-only plan) + non-finite guard + partial pivoting; real cables carry an R_dc loss floor anyway |
| Stamp sign/convention bugs (classic MNA failure mode) | Pi-vs-TwoPort.Line property test (1e−12) + chain-vs-nodal equivalence over a lossy network (1e−9) |
| Exact-short handling (merged nodes, port-to-ground) producing degenerate assemblies | Union-find handles node–node and node–ground uniformly; explicit early-out Γ = −1; dedicated folding tests |
| Lattice ground truths mis-derived | Each series re-derived in test comments from the junction rule ρ = (2−m)/m, τ = 2/m; every series' sum must equal the independently-computed Γ(0) — a self-check inside the tests |
| LU perf at n ~ 31 | Thread-local workspaces, no allocation in the frequency loop; plan-caching lever held in reserve; stress case asserts loosely (≤ 500 ms) with the real number logged |
| Ring echo paths longer than the window heuristic expects | TotalCableDelayS bound + geometric decay of recirculation + Settled flag; window override already exists |
